# 列生成重做报告：Python + Gurobi 直接定价（`src/cg_gurobi`）

- 分支：`feat/cg-gurobi-direct-pricing`（基于 `main` 30306d8，已合并远端 main 的 Formal24 数据 92a275a）
- 日期：2026-09-24
- 环境：macOS，8 核，Python 3.12.13（`.venv`），Gurobi 12.0.3（完整许可），HiGHS 1.11（旧实现）
- 关联文档：`列生成正确性审计.md`（旧实现审计，本次重做的起因）、`benchmark/汇总对比.md`（全部对比表，由 `scripts/build_cg_report.py` 生成）

## 1. 为什么重做

对旧 HiGHS 列生成（8100 行单文件）的审计用穷举复现了三处高严重度证书缺陷（CG-01 假下界、CG-02 历史候选越过分支域、H2 搬运界键错位）及其放大链路，三者叠加可在零次精确定价的情况下输出 `proven_optimal=True`；同时探针测量显示四个定价器的调度在真实数据上退化为两个半（标签 DP 从未启用、大组 DFS 从不闭合但每次先跑满 3–15 秒再转 MIP），并存在哈希级的同对偶重复求解。结论是旧实现的 U 与 `proven_optimal` 不可信，遂决定归档旧代码、仅沿用其建模信息、以 Gurobi 从零重写直接定价列生成。

## 2. 建模

以下全部取自 `docs/任务需求、数学模型与实现说明.md` 第 3–6 章，并以 `src/allocation_evaluator.py` 为业务语义的唯一裁判；实现中所有软分系数直接调用评估器函数计算，保证列成本与独立评分逐位一致。

### 2.1 集合与可行域（`instance.py`）

- 组 g、旅客 p、目标座位 s；分舱后每个舱位独立建模。
- 可行域 D_p：舱位一致；固定座位 `newSeat` 只保留该座；出口排按 SSR 规则 `allow_exit_row`；`requires_bassinet`/`requires_aisle` 座位属性；双侧保护旅客在 `require_two_real_neighbors=True` 时要求恰有两个真实邻座（`row_neighbors`，是否跨过道由 `both_side_empty_allow_cross_aisle` 决定）。
- 输入层校验：混舱组、重复 (groupId, hostnum)、固定座位缺失/冲突/不满足属性、分舱容量必要条件（真实旅客 + 固定保护空座需求 ≤ 舱位座位数，§4.10）均直接拒绝。
- 个人软分 h_ps = 距离 + 价值 + 属性偏好（`individual_assignment_components`）；紧凑度 F_c = w_c·(βx·max|X−X̄| + βy·max|Y−Ȳ|)；婴儿系数 B(u,v) = `baby_interference_score`（同子排或前后排、同舱、有向）。

### 2.2 定价子问题 MP2（`pricing.py`，每组一个持久化 Gurobi MIP）

变量：x_ps ∈ {0,1}（s ∈ D_p）；单侧保护 z_pst ∈ {0,1}（t ∈ N⁰(s) 子排邻座）；紧凑度 dev_x, dev_y ≥ 0；条件 SSR 激活 e_ℓ ∈ {0,1}；同组婴儿对 w_uv ∈ [0,1]。

约束：
- 全员分配 Σ_s x_ps = 1；
- 单侧保护 Σ_t z_pst = x_ps；
- 物理资源 R_t = Σ_p x_pt + Σ z_{p s t} + Σ_{p 双侧} Σ_{s: t∈N(s)} x_ps ≤ 1（组内互斥，与主问题座位行同口径）；
- 陪护 x_ps ≤ Σ_{q∈E_g, q≠p} Σ_{t∈N_p(s)} x_qt，E_g 为评估器 `_is_adult_caregiver` 定义的合格陪护者，N_p(s) 是否跨过道按 SSR 规则与 `needCared` 语义；无合格陪护者时 x_ps = 0；
- 紧凑度 dev_x ≥ ±(Σ_s X_s x_ps − (1/n)Σ_p Σ_s X_s x_ps)（w_c ≤ 0 时精确）；
- 条件 SSR：e_ℓ ≥ x_ps 对带标志旅客与 s∈ℓ；类型人数 m_ℓτ = Σ_{p: ssr=τ} Σ_{s∈ℓ} x_ps；
- 同组婴儿：w_uv ≥ I_u + O_v − 1，w_uv ≤ I_u，w_uv ≤ O_v。

目标（最小化约化成本）：c_k − π_g − Σ_t λ_t R_t − Σ μ^e e_ℓ − Σ μ^m m_ℓτ − Σ ν_uv (I_u + O_v)，其中列成本 c_k = −Σ h_ps x_ps + |w_c|(βx dev_x + βy dev_y) + Σ_{同组对} B(u,v) w_uv。列生成后用评估器函数独立重算成本，与 MIP 目标差超过 1e-5 即抛错（自审计）。

证书：Gurobi `Optimal` → 精确最小约化成本；`Cutoff=-tol` 报 `CUTOFF` → 证明不存在负列；`TimeLimit`/早停 → 下界取 `ObjBound`，不冒充证书。

### 2.3 受限主问题 MP1（`master.py`，Gurobi LP）

- 组凸性 Σ_k y_gk + art_g = 1；座位资源 Σ a_gks y_gk ≤ 1；
- 条件 SSR：a_ℓτ ∈ [0,1]，每个带标志组 Σ_k e_kℓ y_gk − a_ℓτ ≤ 0，Σ_{g,k} m_kℓτ y_gk + M_ℓτ a_ℓτ ≤ M_ℓτ + 1；
- 婴儿：Σ_k (i_ku + o_kv) y_gk − b_uv ≤ 1，b_uv 成本 −B(u,v) ≥ 0；列成本预先加上同组对的 B，使整数解中同组影响恰好抵消；
- Phase I 最小化 Σ art_g（列成本置 0），人工列为 0 后固定 art 上界为 0 并恢复真实成本。

### 2.4 主循环与证书（`solver.py`、`branching.py`）

```
按舱位分块（座位少的舱先算，剩余时间给最大舱）
  初始列：项目 5 s 启发式的完整方案 → 全局匹配协调单侧保护空座 → 拆成各组列；缺组用零对偶贪心补
  循环：解 LP → 取原始对偶 → 各组并行定价（6 线程，早停：找到 ≤ 0.3×上轮最小 rc 的列即停）
        → 加入 rc < −tol 的列 → 无新列且全组 Optimal/Cutoff ⇒ 根 LP 认证；有组超时 ⇒ 加倍时限重试
  潜水：固定 LP 值最大的分数列并继续定价（只扩列池，不动界）
  列池整数 MIP（启发式列作 MIP start；失败回退启发式方案）
  分支定价：按 (组 g, 座位 s) 是否占用二分，最优先搜索，节点内完整列生成，节点整数启发式，
            所有节点认证且前沿为空 ⇒ proven_optimal
  合并：整数解经独立评估器复核（硬违规必须为 0、软分必须等于列成本之和）；U 求和仅当全部舱位有证书
```

三级证书：精确 U（根 LP 全组闭合）、安全 U（L_RMP + Σ min(0, lb_g)，lb_g 为 ObjBound）、无 U；`proven_optimal` 只在分支定价前沿清空且全部节点认证时为真。

## 3. 正确性验证

1. **穷举对照**（`tests/test_cg_gurobi.py`）：6 个语义场景（普通组、单双侧保护、陪护 + 出口排、条件 SSR 隔离、跨组婴儿、固定座位 + 保护），旅客—座位全排列求全局最优，断言 U ≥ 最优且 I = 最优。全部通过。
2. **公开验证集 11 例**：完整合法、软分与评估器逐位一致、旧实现证明过的 LP 值逐位复现、两个满载算例证明最优（-116.79、-122.025，与旧实现分支定价结果一致，5 个节点对 279 个）。
3. **无效输入**：混舱组、超容量输入在入口被 `ValueError` 拒绝。
4. **自审计**：每次定价的 MIP 目标与按主问题系数重算的约化成本比对；每个整数解的列成本之和与评估器软分比对；两者不一致即抛错，从未触发。
5. **对抗式审计**：对新实现运行五维度（硬约束保真、目标一致性、证书有效性、鲁棒性、测试覆盖）独立审计并逐条驳斥核查，结果见第 6 节。

## 4. 实验设计

- 数据：公开验证集 11 例（6–23 人）；Formal24 官方 24 例（正向 3-4-3→3-3、反向 3-3→3-4-3，50/100/150/full × normal/stress/edge）。两者均为旧实现正式协议使用过的数据，不另加自生成算例。
- 方法：项目启发式 5 s（V1 生产口径）；旧列生成 150 s（归档版，含其分支定价）；新列生成 150 s（默认配置）；Formal24 另列冻结的 Rich Python 60 s 参考分与历史最好整数解 I（`rich_python_formal24.csv`）。
- 指标：完整合法（硬违规、未分配）；软分及 s/v/p/c/b 分项；LP 上界及证书类型（证明最优 / 精确 U / 安全 U / 无）；相对自身界的 gap；耗时。全部由独立评估器重算。
- 机器同上，串行运行避免计时干扰；新方法 6 个定价线程，旧方法 4 个（其默认）。

### 5.3 收敛的决定因素

收敛主要取决于最大同行组人数：最大组 ≤7 人的 10 例 600 s 内全部认证（8 例 150 s 即认证）；最大组 8 人的 4 例半数认证；含 9–10 人组的 10 例中仅 50_edge（150 s 证明）与正向 100_edge（600 s 根 LP）认证，其余 7 例 gap 2.4–32.7%。edge 档每例含 2–6 个 ≥7 人组、1–4 个 9–10 人组，其定价 MIP 在单次时限内不能证明无负列，是瓶颈；正向 full_edge 还叠加保护空座密集导致的松弛弱（900 s 单线程诊断 gap 33%）。再加总时间收益递减，改进方向是大组定价子问题（对称性消除、排块子结构）与松弛加强（保护空座 clique 割）。


## 6. 对新实现的对抗式审计与修复

审计方式：5 个维度（硬约束保真、目标一致性、证书有效性、鲁棒性、测试覆盖）各由一个独立审计者阅读代码并构造反例，25 条原始发现逐条交给 2 个持怀疑立场的核查者尝试驳倒（允许运行 5 秒内的小实例复现），最后由完整性评审列出未覆盖项。结果：22 条成立（均被复现）、3 条被驳回。按根因归并并修复如下。

| 严重度 | 缺陷 | 修复 |
|---|---|---|
| 高 | 分支定价把"(组,座位) 用量已整数但 y 仍分数"的节点当作整数解，用 LP 值冒充成本，可产出评估器判非法的方案并标 `proven_optimal`（审计者用 6 座 3 人的条件 SSR 反例复现） | 新增旅客级分支 (组,旅客,座位)；只有所有 y∈{0,1} 才视为整数点；LP 整数点与节点 MIP 结果都必须通过独立评估器（硬违规 0、成本重算）才能成为 incumbent；两级都无可分支用量而 y 仍分数 → 节点标未认证 |
| 高 | 受限主问题 LP 不可行被当作节点不可行并关闭（没有 Farkas 定价），`proven_optimal` 不可靠 | 节点级 Phase I：放开人工列、用 Phase I 对偶定价，只有人工列仍为正且全组闭合才认证不可行；否则标未认证 |
| 高 | 多个定价器共享同一 Gurobi Env 而线程池任意调度，违反 Gurobi 线程安全契约 | 每个定价器独占一个 Env |
| 高 | 整数阶段预留 2 秒硬底，小预算/小舱位下列生成窗口为负、完整的贪心初始列被丢弃 | 预留 = min(配置, 15%预算)，无硬底；每轮单组时限不超过剩余时间 |
| 中 | 分舱求解只传该舱旧座位图，原座位在其他舱的旅客个人分被算成 0，与评估器不一致 | 旧座位图整张传入（仅用于评分） |
| 中 | 顶层 `solve()` 把某舱已认证的不可行擦成 `incomplete` 且 `total_score=0.0`；不可行返回缺少大部分字段 | 不可行贯通到顶层 `status='infeasible'`，字段齐全 |
| 中 | `require_two_real_neighbors=False` 时容量必要条件把双侧保护按 +2 计，拒绝可行输入 | 该配置下双侧只按本人 1 座计 |
| 低 | `w_b` 符号未校验（单侧线性化只在 w_b ≤ 0 时精确）；`oldSeat: null` 抛 AttributeError；字符串 `groupId/hostnum` 与评估器原始键不匹配；重复 `groupId` 未拒绝；固定座位落在另一固定双侧旅客的保护空座上未拒绝（§4.4）；`result['dive']` 恒为 None；CLI JSON 含 `Infinity`；README 对 `total_score` 校验的表述过强 | 全部修复：入口校验 + 输出清洗 + 文档措辞 |
| 中（评审补充） | 启发式失败时没有完整整数兜底 | 资源互斥的完整贪心方案经评估器验证后作为 MIP start 与兜底 |

被驳回的 3 条：异常路径下 Env 未释放（实际有释放）；启发式时限未按舱位截止裁剪（影响可忽略）；字符串 id 由评估器容忍（实际会导致键不匹配，已改为入口拒绝）。

新增 5 个回归测试覆盖上述反例（同座位排列分支、跨舱旧座位评分、认证不可行、id 校验、2 秒微预算），与原有 3 组测试合计 8 个全部通过。**审计确认的问题都出现在分支定价与鲁棒性层，根 LP 界与列成本一致性未发现问题**；修复前跑出的基准数字中，新方法的整数解与 U 不受影响，但 `proven_optimal` 标记不可信，因此全部新方法结果均以修复后代码重跑。

### 6.1 LP 松弛强度的观察

在官方 forward:full_edge 上的 900 s 单线程诊断结果见 HTML 报告 7.1 节（自动填入）。
