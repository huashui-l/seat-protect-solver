    5 / 20 / 60 秒如何控制

    总截止时间 + 阶段预算 + 自适应搜索

    1. 总截止时间

    求解函数开始时建立单调时钟截止点。准备、构造、优化与内部验收共用预算；独立舱位也共享同一个总时限。接近截止时停止启动新搜索，并预留结束与验收时间。

    2. 每阶段分配时间

    候选生成、联合重组、可行性恢复与局部修复各有子预算。原生优化器的搜索上限取阶段预算与总剩余时间的较小值；建模阶段也检查总截止点。

    3. 调整搜索强度

    更长预算允许更多候选与迭代；停滞时扩大释放的旅客组范围。单次 LNS 优化通常限制在 0.15 或 0.45 秒，再根据剩余时间决定是否继续。始终保存本次运行的最好合法解。

    60 秒是搜索上限；首次完整解的实际时间另见收敛表。程序可以报告已验收解的改善轨迹，但尚未实现经全量验证的停滞提前停止策略。增加时间不会放宽硬约束或改变目标权重。三个预算独立运行，阶段安排与墙钟截断会影响搜索路径，因此跨档得分不保证逐例单调。此处采用带检查和预留的截止机制，原生优化器结束过程并非操作系统级强制中断，仍需检查实际耗时。程序启动、依赖导入、输入文件读取、结果写盘及额外外部审计不计入求解函数计时。

    02 / METHOD一种组合数学启发式

    Matheuristic · Pattern Recombination + Adaptive LNS

    它不依赖训练好的神经网络，也不读取历史解作为起点。Python 组织搜索，NumPy / SciPy 计算候选，CP-SAT 与 HiGHS 求解受限子问题；每次接受完整解前都调用原项目评估器重新验算。

    1 · CONSTRUCT构造合法候选

    从原始输入出发，把同组旅客、陪护和保护空座组合成候选分配。

    2 · COMBINE解决组间冲突

    联合选择各组方案，满足座位互斥与原模型的跨组规则。

    3 · IMPROVE反复局部改进

    先快速换座，再释放相互阻塞的若干组，用原模型重排。

    4 · VERIFY验算并保留最好解

    所有方案用同一个原始评估器验收，到时返回本次最好合法解。

    目标、输入人数、固定座位、陪护、保护空座和 SSR 规则均来自原模型。候选和邻域是搜索范围的限制；它们可能漏掉更好的解，但不会把违反原模型的方案当作合格解。下面的实现细节服务于这四个阶段。

    展开完整实现步骤
    01 · MODEL读入模型并分舱

    保留完整座位图坐标。独立舱位共用总时限；婴儿座位对匹配先检验必要容量。

    02 · SHAPES构造完整组模式

    各档先共用快速构造尺度，再扩大候选池。固定座位及确定的保护空座先保留，紧凑形状围绕实际可用资源生成。

    03 · MATCHING特殊旅客枚举 + 匈牙利匹配

    枚举 SSR、陪护和保护位置；在选定占座集合上精确匹配普通旅客身份，消除排列对称。

    04 · CONSTRUCTION后悔值构造初始方案

    密集场景先做限时回溯装箱，再按后悔值构造；位集判断互斥，按剩余空座补充模式。保留合法部分方案作为恢复提示。

    05 · MASTER联合选择组模式

    初始紧凑模式池用 CP-SAT 选择每组一个方案。60 秒档前段在时间充足时使用 HiGHS 全池重组；短子问题和尾段使用紧凑 CP-SAT。占座、保护和跨组影响均保留。

    06 · DESCENT向量化换座与模式变形

    成人换座、空座迁移、受保护座块迁移及整组平移，以低开销消除局部损失，再联合重组。

    07 · LNS自适应大邻域修复

    释放损失大、阻塞、邻近或随机的组，用直接旅客—座位模型修复；停滞时扩大邻域，定期为已释放旅客开放完整座位域；其他组仍锁定。

    08 · AUDIT独立验收与保留最优已知解

    只有全员分配、零硬违规且软分改善的完整方案进入轨迹。小实例可给全域最优证书，大实例明确区分“好解”与“已证最优”。

    目标函数没有被换掉

    max F = Fs + Fv + Fp + Fc + Fb

    依次为座位变动、座位价值、偏好、同行组紧凑度和跨组婴儿影响；分项已乘原权重。未分配人数与硬违规必须都等于 0，不能用高软分抵消。

    紧凑度仍采用组内相对重心的最大横向 / 纵向偏差。CP-SAT 使用精度缩放后的整数线性表达，最终分数由原浮点评估器计算。

    为什么这样组合

    直接为所有旅客建立全域整数模型，短时搜索容易花在构模和排列上。完整组模式把保护与陪护关系提前处理，匹配压缩普通旅客的排列空间，联合选择解决组间资源竞争。

    模式集不可能一次覆盖所有好方案，所以使用真实余座补全、模式变形和直接模型大邻域，让搜索能够离开初始模板。较长档位增加候选和修复机会，而不是改目标函数。

    03 / OPERATORS算子、约束与设计理由

    算子执行的操作为什么需要
    多比例紧凑形状横纵比例与锚点多样化；为每组生成准确资源数及带备用位置的候选。兼顾换座距离与组紧凑度，给联合选择保留位置多样性。
    保留固定资源先扣除已固定的占座和确定保护资源，再把本组固定锚点并入候选。密集场景中固定座位打散可用区域；避免大量候选从一开始就必然冲突。
    特殊枚举 / 身份匹配特殊旅客有限枚举；普通旅客用 Hungarian 最小成本匹配；强制必要陪护位置被成人占据。同一占座集合的紧凑度相同，无须对所有普通旅客做阶乘枚举。
    后悔值 + 剩余资源补全优先处理可选方案少的组，改变资源压力排序重启；缺失模式时按真实空座生成新形状。提高第一份完整解的成功率，修复静态模式在满载时的拼接缺口。
    模式联合重组每组恰选一模式；占座与保护空座互斥；条件 SSR、婴儿跨组影响保留原语义。允许多个组同时让位，跳出逐组贪心的局部最优。
    成人交换 / 空座迁移向量化计算个体项、精确重心偏差及婴儿影响；保留成人陪护覆盖。快速消除大量简单换座损失，把整数求解时间留给更难的跨组动作。
    保护座块迁移特殊旅客与其独占保护空座协同移动；重新匹配同组普通旅客。保护资源必须与旅客一起移动，单座移动常会被合法性限制卡住。
    整组平移 / 单座变形移动整组资源形状，或替换形状中的一个座位；把新模式交给联合重组。补足最初的几何模板，改善固定锚点和碎片空位周围的分配。
    阻塞 / 邻近 / 随机 LNS释放根组、其目标资源的占有组以及邻近组；同时识别保护空座的所有者。既围绕当前损失定向改进，也通过随机和周期覆盖避免长期忽略其他组。
    全域可行性恢复模式组合失败后使用直接模型；必要时临时去掉软目标先满足硬约束。候选模式失败不等于数学模型不可行。先获得合法解，再优化原始软分。

    算子计数表示执行 / 生成次数，不等于各算子的独立贡献。没有独立消融实验时，不把整体提升归因于某一个算子。

    05 / VALIDITY约束、输入可行性与最优性

    每份完整方案经过双重核验

    求解时每次接受完整解都检查全部硬约束和原始软分；实验结束后再次从磁盘读取保存的分配独立复算，同时核对输入和座位图 SHA-256、目标值、全域上界及改善轨迹。

    小规模回归包含穷举最优值对照、整数化界的误差、保护空座独占、同组成人照顾多名儿童、固定锚点、模式主问题评分和限时状态。模型的辅助变量可能留有保守松弛，因此验收采用解码后的原始目标。

    如何理解“最优”

    已证全局最优：完整域模型提供安全上界，且与当前合法解分数的差不超过 10−6。上界考虑整数系数与坐标缩放误差。

    已找到的最好合法解：缺少全域最优证书的大实例。受限模式池或某个邻域求到最优，并不能证明原问题全局最优。

    限时未求出：在指定预算内没有完整解，不等于输入不可行。只有全域不可行证明或独立结构性证书才能作不可行结论。

    本实验按一次固定 seed 的完整批次报告，没有逐例挑选多个运行的最高成绩。多线程调度和时间截断会造成波动；5 / 20 / 60 秒独立运行间也不保证逐例单调。这些测试数据也用于开发调参，尚未通过未见测试集验证泛化。

    06 / REPRODUCIBILITY对算力做了什么优化

    针对短时搜索的工程优化

    使用 NumPy 向量化形状评分与换座增益；缓存几何形状和排名；位集快速检测资源冲突；用匈牙利匹配消除普通旅客的排列对称。初始候选池按好分数与排覆盖压缩，需求达到容量 95% 时扩大覆盖。

    M5 的 10 核上，初始模式与直接修复使用最多 8 个 CP-SAT 搜索线程；60 秒档后续模式重组使用 1 个线程，以控制末段退出延迟。HiGHS 保持单线程。各算例串行运行，避免几个限时求解器相互抢占 CPU。没有 M5 专用机器码、GPU、算例 ID 特判或根据参考答案硬编码。

    大池 HiGHS 只在子预算至少 10 秒、并额外留下至少 10 秒总预算时启用；20 秒档和尾段使用紧凑 CP-SAT，避免大池预处理挤占收尾时间。这些属于算法结构与常规 CPU 优化。5 / 20 秒使用同一已完成版本，60 秒使用收紧末段时限的新版本，逐档源码与差异保存在归档中。没有做完整线程数 / 平台消融，因此不宣称 8 线程对所有机器都是最佳配置。

    计时与比较范围

    时间从调用求解函数开始，包含公共模型准备、构造、求解、内部核验和结果组装。进程启动、依赖导入、读取 JSON、磁盘输出及额外的外部复核不计入函数计时。

    预算是协作式墙钟截止，预留结束时间；原生求解器关闭与 Python 构模并非可强制瞬停。表格如实记录调用总耗时，并单列所有超过预算的记录，不把请求上限冒充实际用时。

    在 30 个历史可比案例中，三份输入哈希及数学目标 / 约束参数与 C++ 逐项匹配。主要实验为 V2 的 72 例。Formal24 24 例和 D4 16 例已完成的基础数据保留作补充，后续先不追加这些数据集的实验。原 Windows C++ 只有非 V2 的 30 例历史记录；本轮另用未改动的历史源码在本机完成 72 例 V2 复测，并单独标记。
